# naive-bayes-sample

文章が「赤ちゃん言葉」「お母さん言葉」「その他（普通の文章）」の
どれにどれくらい近いかを判定する、教育用の機械学習サンプルです。

「えんじいろ」プロジェクトの AI 担当メンバーが、機械学習の処理を
自分の手で書いたことが無くても、**中でどんな計算が行われているのか**を
実際に読んで・動かして理解できるようにすることを目的に作っています。
scikit-learn のような機械学習ライブラリは使わず、`app/classifier.py` に
アルゴリズムそのものを一から書いています。

## 1. これは何をするものか

`predict` という関数（または API）に文章を渡すと、次のような結果が返ってきます。

```json
{
  "text": "ばぶー ねむいよぉ、おしごとつかれたでちゅ",
  "probabilities": {
    "赤ちゃん": 82.3,
    "お母さん": 10.1,
    "その他": 7.6
  },
  "predicted_class": "赤ちゃん"
}
```

3つの数値を足すとだいたい 100 になります（「赤ちゃんらしさ 82.3%」
「お母さんらしさ 10.1%」「どちらでもなさそう 7.6%」という意味）。

## 2. 「ナイーブベイズ」って何？（仕組みのざっくり説明）

詳しい説明は `app/classifier.py` の冒頭コメントに書いていますが、
考え方だけ先にざっくり説明します。

1. **学習**：あらかじめ「赤ちゃん言葉の例文集」「お母さん言葉の例文集」
   「その他の例文集」を読み込んで、それぞれの中に**どんな単語がどれくらいの
   頻度で出てくるか**を数えておきます。
   例えば「赤ちゃん」の例文集には「ばぶ」「でちゅ」「ねむい」がよく出てきて、
   「お母さん」の例文集には「よしよし」「えらいね」「大丈夫」がよく出てくる、
   といった統計を作るイメージです。

2. **予測**：新しい文章が来たら、その文章を単語に分割し、
   「この単語の組み合わせは、赤ちゃんの例文集・お母さんの例文集・その他の例文集、
   どれに一番近い頻度で出てきそうか」を確率として計算します。

3. どのクラスの確率が一番高いかで、最終的な判定結果が決まります。

「ナイーブ（素朴）」という名前は、「文章中の単語は、他の単語と関係なく
バラバラに出現する」という単純化した仮定を置いていることに由来します
（実際には単語同士につながりがありますが、そこは無視して計算を簡単にしています）。

## 3. ディレクトリ構成

```
naive-bayes-sample/
├── README.md
├── requirements.txt
├── data/                     # 学習用データを置く場所
│   ├── 赤ちゃん/               # 赤ちゃん言葉の例文（JSONファイルを何個でも置ける）
│   ├── お母さん/               # お母さん言葉の例文
│   └── その他/                 # どちらでもない普通の文章の例文
└── app/
    ├── tokenizer.py           # 文章を単語に分割する処理
    ├── data_loader.py         # data/ 配下の JSON を読み込む処理
    ├── classifier.py          # ナイーブベイズ分類器（アルゴリズム本体）
    └── main.py                # FastAPI アプリ（Web API として動かす入り口）
```

### 学習データの入れ方

`data/赤ちゃん/`・`data/お母さん/`・`data/その他/` のそれぞれに、
**文章（文字列）の配列を書いた JSON ファイル**を好きな数だけ置いてください。
ファイル名は自由です。同じディレクトリに複数ファイルを置くと、
自動的にすべてまとめて読み込まれます。

```json
[
  "ばぶー ねむいよぉ",
  "おぎゃー おなかすいたでちゅ"
]
```

サンプルとして各ディレクトリに `sample.json` を用意してあります。
実際に学習に使うデータは、この形式に沿ってどんどん追加していってください
（データが多いほど、判定の精度は上がりやすくなります）。

## 4. セットアップ

Python 3.10 以上を想定しています。

```sh
# 仮想環境を作る（1回だけ）
python3 -m venv .venv

# 仮想環境を有効化する（ターミナルを開き直すたびに必要）
source .venv/bin/activate   # Windows の場合は .venv\Scripts\activate

# 依存パッケージをインストールする
pip install -r requirements.txt
```

## 5. 動かし方

### 5-1. 各ファイルを直接実行して、仕組みを1つずつ確認する

このリポジトリの `app/` 配下のファイルは、それぞれ単体で実行すると
動作確認ができるようになっています（`if __name__ == "__main__":` の部分）。
上から順番に試すと、処理の流れを追いやすいです。

```sh
# ① 文章がどう単語に分割されるかを確認する
python app/tokenizer.py

# ② data/ 配下の学習データが正しく読み込めているかを確認する
python app/data_loader.py

# ③ 学習 → サンプル文章の判定、を一気通貫で確認する（メインはここ）
python app/classifier.py
```

`python app/classifier.py` を実行すると、次のような流れがすべて
1つのコマンドで確認できます。

1. `data/` 配下の学習データを読み込む
2. 分類器を学習させる
3. あらかじめ用意したサンプル文章をいくつか判定し、確率の内訳を表示する

### 5-2. サーバーを立てて、API として使ってみる

```sh
python app/main.py
```

起動すると `http://127.0.0.1:8000` でサーバーが立ち上がります。
ブラウザで次の URL を開くと、対話的に API を試せる画面（Swagger UI）が出てきます。

```
http://127.0.0.1:8000/docs
```

`curl` から呼び出す場合はこうです。

```sh
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"text": "ばぶー ねむいよぉ、おしごとつかれたでちゅ"}'
```

レスポンス例：

```json
{
  "text": "ばぶー ねむいよぉ、おしごとつかれたでちゅ",
  "probabilities": { "赤ちゃん": 82.3, "お母さん": 10.1, "その他": 7.6 },
  "predicted_class": "赤ちゃん"
}
```

### 5-3. Python のコードから直接関数として呼び出す

API を経由せず、Python のプログラムから直接判定したい場合は、
`NaiveBayesClassifier` クラスを直接使えます。

```python
from app.classifier import NaiveBayesClassifier
from app.data_loader import load_training_data

classifier = NaiveBayesClassifier()
classifier.fit(load_training_data())

result = classifier.predict_proba("よしよし、今日もよく頑張ったね")
print(result)  # {"赤ちゃん": 5.2, "お母さん": 88.9, "その他": 5.9} のような辞書が返る
```

## 6. コードを読む順番のおすすめ

初めて読む場合は、次の順番がおすすめです。

1. `app/tokenizer.py` … 文章を単語に分割する部分（一番シンプル）
2. `app/data_loader.py` … 学習データを読み込む部分
3. `app/classifier.py` … ナイーブベイズのアルゴリズム本体（一番大事な部分。
   冒頭のコメントに数式の意味も説明してあります）
4. `app/main.py` … これらを Web API としてまとめる部分

## 7. このリポジトリでは扱っていないこと

- 実運用に耐える精度・速度のチューニング
- scikit-learn 等の既存ライブラリを使った実装（あえて使っていません）
- 学習データそのもの（サンプル以外の大量データは、各自 `data/` 配下に追加してください）
- 「えんじいろ」本体（`engiiro-app`）との自動連携。まずはこのリポジトリ単体で
  仕組みを理解することを優先しています。将来的に本物のAI評価として組み込む場合は、
  別途 API 連携の設計が必要です。
