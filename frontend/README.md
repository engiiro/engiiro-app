# frontend

「えんじいろ」の画面。**React + TypeScript + Vite**（技術選定は人間 `shitake-zense` の決定。Fresh は使わない）。

PC を主にした 3 カラム構成の SPA。backend（Deno / `docs/design_doc.md` §7）に JWT で接続する。

| ディレクトリ | 中身 |
|---|---|
| [`app/`](app/) | 本体。画面の実装はすべてここ |
| [`images/`](images/) | 画像の原本。イラストはテーマごとに3ファイルの SVG、名乗りは手書きの PNG |
| [`color-check/`](color-check/) | 配色を決めるための使い捨てページ。**UI・レイアウトを画面設計の参考にしない**（`DESIGN.md` §10.1-4） |

### 画像の置き場所

`images/` が原本、`app/public/` が配るもの。**SVG は同じ中身の複製**なので、
どちらを見ても同じものが読める。

例外が1つある。名乗りの手書き画像 `engiiro.png`（園児UI でだけ「えんじいろ」の文字と
差し替わる。人間の指示、2026-09-05）は、原本が 1448×833・581KB のスキャンなので、
`app/public/images/` 側には **720px 幅・64色に落とした 43KB の複製**を置いている。
園児UI では毎ページ読み込まれるものなので、原本のまま配ると重すぎる。
描き直したときは、原本を差し替えたうえで配る側も作り直すこと。

正本の階層は [`../AGENTS.md`](../AGENTS.md) → [`../docs/specification.md`](../docs/specification.md) →
[`../docs/design_doc.md`](../docs/design_doc.md) → [`../DESIGN.md`](../DESIGN.md) の順。**上が常に優先**。
画面を作る前に `DESIGN.md` §0「Non-Negotiables」を読むこと。

| スタイル | 素の CSS + カスタムプロパティ（コンポーネント単位の `.css`） | — |

### 入れなかったもの

`package.json` の `dependencies` は **`react` と `react-dom` の2つだけ**。次のものを意図的に入れていない。

| 入れなかったもの | 代わりにどうしたか |
|---|---|
| ルータ（react-router 等） | 画面の居場所を `Location[]` の配列1本で持つ（後述） |
| 状態管理（Redux / Zustand / TanStack Query 等） | `useState` + `data/api.ts` の1境界。共有したい状態が App の外に出ていない |
| UI ライブラリ（MUI 等） | `DESIGN.md` が色・余白・動きまで決めているので、寄せる先が既にある。上書きするコストのほうが高い |
| CSS フレームワーク / CSS-in-JS | トークン（CSS 変数）で足りる。テーマ切替が `<html data-theme>` の1属性で済む |
| アイコンパッケージ | `components/icons.tsx` に `currentColor` で自前定義（`DESIGN.md` §11 でセット未定のため差し替え前提） |

規模は `src/` で約 14,700 行（コンポーネント 29・画面 12・lib 14・data 8）。
この規模で依存を足すと、**足したものの流儀に合わせて `DESIGN.md` を曲げる**ことになるので入れていない。

## 設計で通した芯

以下は「そう書いた」ではなく「**なぜそう書いたか**」。同じ判断を後から迷わないために置いている。

### 1. 色は役割名でしか触らない

[`src/tokens/`](app/src/tokens/) の4ファイル（`base` 余白/寸法・`theme` 色・`typography` 書体・`motion` 動き）に
値を集め、コンポーネントは `var(--accent-line)` のような**役割名**しか参照しない。

> 生の hex が書かれているファイルは [`tokens/theme.css`](app/src/tokens/theme.css) **1つだけ**。
> ほかの CSS・`.tsx` には 0 件（`grep` で検証できる状態を維持している）。

テーマは `system / normal / dark / kid`（園児UI）の4択で、実際に効く配色は3種類。
実装契約は「素の `:root` に既定を全部置く → OS のダークは明示指定が無いときだけ効く → `[data-theme]` が常に勝つ」の順。
**メディアクエリや `[data-theme]` の中だけで定義される色を作らない**ので、どの経路でも未定義の役割が出ない。

こだわった点が1つ。せってい画面のテーマ見本は「選ぶ前にどんな色か」を見せる必要があるが、
そこに hex を写すと `theme.css` と二重管理になって必ずずれる。
なので各テーマのブロックを `:root` だけでなく**入れ子の `[data-theme]` にも効かせた**。
値を複製せず、セレクタを1つ足すだけで見本が本物と同じ色になる。

### 2. ルータを入れず、「来た道」を配列で持つ

中央の列に出ている場所を `Location`（`view` / `public` / `bubble` / `soothe`）として表し、
`App` が持つのはその**配列**だけ。「もどる」は配列を1つ削る操作になる。

- タイムライン → バブル詳細 → 投稿者のプロフィール → そこのバブル、と潜っても、戻ると**通ってきた道を1段ずつ**返る（以前はホームに着地していた）
- 左サイドの選択表示は、配列を末尾から遡って最初の `view` を探す。潜っていても「来た列」が光ったまま
- URL を持たないので、ルータの設定・パスの二重定義・404 の面倒が丸ごと無い

### 3. サーバとの境界は1ファイル

画面は [`data/api.ts`](app/src/data/api.ts) しか呼ばない。`fetch` と JWT の面倒は
[`data/apiClient.ts`](app/src/data/apiClient.ts) に閉じている。

この線を引いておいたおかげで、**ダミー JSON（`public/data/*.json`）から実 API への差し替えが `data/` の中だけで済み、
29 のコンポーネントと 12 の画面を1行も触っていない**。`AiUnavailableError` のような区別も、境界側で型に起こしてから画面へ渡す。

トークンは `localStorage`（`engiiro.token`）。`localStorage` が使えない環境（プライベートモード等）では
`try/catch` で握りつぶし、そのセッション限りの動作に落とす。読めないことを理由に画面が死なない。

### 4. モックの状態は画面ではなく URL に置く

「AI が止まっている」「フィードが空」のような**操作だけでは作れない状態**は、
以前は画面上部の帯（`MockControls`）で切り替えていた。製品の UI でないものが常に一番上を占め、実機の縦幅も食っていたので URL に退避した。

```
?feed=empty|loading   ?ai-eval=off   ?ai-transform=off   ?entry=intro|signup|login   ?theme=dark|kid
```

読むのは [`lib/mockScenario.ts`](app/src/lib/mockScenario.ts) の1か所だけ。この足場は実 API への移行でファイルごと消える。
URL は未検証の入力なので、知らない値は既定に落としてから `state` に入れる。`window` を直接見ず、文字列を受け取るだけの関数にしてある。

### 5. ゲストのボタンを `disabled` にしない

えんじいろはアカウントが無くても読める。書く・反応する・大好きにするだけがログインを要る。

ここで**押せないボタンを出さない**ことにこだわった。押せるままにしておいて、押したら「なぜ要るのか」を出す。
`disabled` で灰色にすると、押す前から「自分には何ができないのか」を想像させることになる。
判定は `App` の `guard` 1か所に集約し、画面ごとに `if (isGuest)` を書かない。

### 6. AI の停止を「評価」と「生成」で分ける

| 止まったもの | 起きること |
|---|---|
| 文章**評価** | バブルもあやすも投稿できない（NFR-003）。投稿の関門なので代替が無い |
| 文章**生成** | 投稿とあやすは続けられる（NFR-001）。書き換えの提案が出ないだけ |

外部サービスの停止を一括りに「AI が使えません」とせず、**続けられる操作は続けさせる**。

### 7. 入力は止めない。止めるのは保存

仕様が禁じているのは 150 文字の**保存**であって**入力**ではない。
弱音を書いている途中で文字が消えるのが、このサービスでいちばん避けたい体験なので、
`textarea` は超過しても受け付け続け、送信ボタンだけを無効にする。

- 文字数は**コードポイント**で数える（サロゲートペアを2文字にしない）
- 本文中のスタンプ記法 `:nemui:` は画像1つ＝**1文字**として数える。カタログに無い id は置換しない（`12:34:56` のような時刻表記がスタンプ扱いされない）
- カウンタは「ふくらんでいく輪」だが、輪だけにせず**必ず数値を添える**（`DESIGN.md` §4 Meter）。数値は読み上げからも読める

### 8. 壊れないための最低限（と、その線引き）

[`lib/floodGuard.ts`](app/src/lib/floodGuard.ts) で守るのは2つだけ。

- **多重送信** … `useSingleFlight`。`ref` で即座に閉じる。`disabled` は `state` の反映待ちなので、**同じフレームに2回届いたクリックは両方通ってしまう**
- **連打** … `useBurstLimit`。落とすときは黙って捨てず一言出す（押したのに何も起きない画面にしない）
- **貼り付け事故** … `capInput` / `maxLength` の天井。**仕様の上限（150 など）より十数倍大きく取る**。ここが先に切ると「入力は止めない」の作法を壊すので、事故の桁にだけ効かせる

> これは安全対策**ではない**。frontend の値はいくらでも書き換えられるので、悪意ある送信は backend でしか止まらない。
> ここが受け持つのは「ふつうに使っている画面が壊れないこと」まで、と明記してある。

**表示に混ぜる前に無害化する** … [`lib/safeText.ts`](app/src/lib/safeText.ts)。制御文字・双方向の上書き（`U+202E` など）・幅ゼロを落とす。掛けるのは `data/apiClient.ts` の fetch の出口**1か所**だけ（画面ごとに掛けると、画面を足したときに掛け忘れる）。

- 消さないもの … 改行とタブ（本文は `white-space: pre-wrap` で出している）、`U+200C/200D`（幅ゼロだが、消すと 👨‍👩‍👧 が3人に割れる）
- やらないもの … HTML の除去。React が文字として出すので元から効かない（`dangerouslySetInnerHTML` はこのアプリのどこにも無い。`<a href>` も1つも無い）

**壊れた保存値で始めない** … `localStorage` は利用者にも拡張にも書ける場所なので、入っているものを信じない。JWT は形（base64url の3節）だけ見て、違えば送らずに捨てる（`data/apiClient.ts`）。テーマも URL のモック指定も、許すものの表と突き合わせてから使う（`lib/useTheme.ts` / `lib/mockScenario.ts`）。**中身の検証はしない**。署名を確かめるのは backend の仕事。

**落ちても白い画面にしない** … [`components/ErrorBoundary.tsx`](app/src/components/ErrorBoundary.tsx)。描画中の例外を受けて、「もう一度 ひらく」と「ほぞんした せっていを けして ひらく」を出す（後者は、壊れた保存値で開くたびに落ちる状態から自力で出るための道。消すのは `engiiro.` で始まる鍵だけ）。受け皿の見た目は `Button` などを使わず自前で描く。落ちた原因がその部品なら、受け皿ごと落ちる。

**固まらせない** … 送信中・読み込み中の印は `finally` で必ず下ろす。通信が落ちると API 呼び出しは例外で抜けるので、素直に書くと `setSubmitting(false)` に届かず、ボタンが「おくっています…」のまま二度と押せなくなる（`ComposePanel` の送信、`SettingsScreen` の名前変更、各画面の skeleton がこの形だった）。成功を出すのは**サーバの返事の `ok` を見てから**（`deleteBubble` は失敗を例外にせず `{ ok: false }` を返す）。

### 9. アクセシビリティは後付けにしない

- **Reduced Motion** … 「動きを消す」ではなく「前庭系に触らない等価物に置き換える」。移動・拡大・跳ね・ぼかしの**原資であるトークンを 0 / 1 に潰す**ので、個々の `@keyframes` を書き直さずに全体が無害化する。等価物が作れない粒子演出だけ `display: none`
- **色だけに頼らない** … エラーは枠色でなく文字でも出す。フォーカスは `outline`（`:focus-visible`）
- **`prefers-contrast: more`** … `hairline` を `body` 寄りに寄せる
- **読み上げ** … `role` 25 箇所・`aria-*` 66 箇所。装飾の SVG は `aria-hidden`、意味のある数値は `.eg-sr-only` で言葉を添える。`aria-live` は騒がしくならないよう超過の一行だけ
- **`color-scheme`** … ブラウザが自前で描くもの（日付入力のカレンダー、スクロールバー、選択中の文字の地）もテーマと同じ側に寄せる。これが無いとダークで日付入力の印が地に沈む
- タップ標的は最小 44px（`--touch-target-min`）

### 10. 3カラム → 2 → 1 の畳み方

| 幅 | かたち |
|---|---|
| 1200px 以上 | 左サイド 220px ／ 中央 600px ／ 右サイド 320px |
| 768–1199px | 左はアイコンだけの 72px。右は畳み、投稿パネルは画面に重ねる |
| 767px 以下 | 1カラム。左サイドは下端のバーへ。**ページそのものを送る**（内側の列だけ送ると端末のアドレスバーの出入りと噛み合わない） |

`position: sticky` の要素は親の content box より下へ行けないので、
スクロールする列に `padding-bottom` を置くと、いちばん下で「バブる」ボタンが跳ね上がる。
下の余白は**実体のある最後の要素**の高さで確保している。下端バーの高さも同じトークンを両者が見る（片方だけ直すとボタンがバーに潜る）。

### 11. `<img>` の SVG にはテーマが継承されない

`<img src>` で読み込んだ SVG に、アプリ側の CSS 変数は届かない。
なので「変数を渡す」のではなく「**ファイルを選ぶ**」。`useResolvedTheme` が
`<html data-theme>` を `MutationObserver` で、OS 設定を `matchMedia` で見張り、
いま実際に効いている配色（`normal` / `dark` / `kid`）を返す。属性を直接見張っているので、テーマの選択を props で配り歩かなくていい。

イラストは3枚を画面ごとに役割分けしている（`orbit`＝入り口／`haven`＝空状態／`drops`＝投稿パネル）。同じ絵を全画面で繰り返さない。

### 12. コードには「決めた理由」を書く

このコードベースのコメントは、処理の説明ではなく**判断の記録**に寄せてある
（「誰がいつ決めたか」「代わりに何を試して駄目だったか」「ここを変えると何が壊れるか」）。
仕様・デザインの正本が4段あり、実装が正本と食い違う箇所（PC 3カラムなど）も存在するので、
食い違いを黙って埋めず、**食い違っていることをコードに書き残す**方針にしている。

## 既知の制限

- `data/mockSource.ts` と `public/data/*.json`、`lib/mockAi*.ts` は実 API 接続後の名残。`lib/mockAiEvaluate.ts` の定数 `MAX_MONTHS` だけがまだ参照されている
- [`app/README.md`](app/README.md) は「backend に接続しないモック」だった時期のまま。歩き方と改修の記録としては有効だが、データ源の記述は古い
- `apiClient.ts` のコメントは `vite.config.ts` の `server.proxy` 前提だが、現状 proxy は設定していない（`VITE_API_BASE_URL` を直接渡す運用）
- 意味色（`--success` / `--warning` / `--error`）は園児UI の値が `DESIGN.md` に無く、3テーマともノーマルの値。現状どの画面でも未使用
- PC 3カラムは `DESIGN.md` §5.2「カラムを増やさない」・§8.1「モバイルファースト」と食い違う。改訂案は別途
- 自動テストは無い。確認は `npm run build`（`tsc -b`）と `npm run lint`、それに URL でのシナリオ切り替えによる手動確認
