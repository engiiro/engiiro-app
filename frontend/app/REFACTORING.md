# SNSフロントエンドの構成と確認手順

この整理は `main` の既存動作を維持するリファクタリングです。API契約、サーバ側の判定、CSS、表示文言は変更していません。

## 責務の置き場所

| 場所 | 責務 |
| --- | --- |
| `src/App.tsx` | 画面の組み立て、認証による操作制限、到着先のデータ取得、更新後の再取得 |
| `src/lib/useNavigationHistory.ts` | SNS画面の履歴、戻り先、サイドバー選択、ログアウト時の履歴リセット |
| `src/lib/useFeed.ts` | フィードの取得・読み込み中・失敗状態。`refresh` はカードを残し、`reload` はローディングを表示する |
| `src/components/BubbleList.tsx` | カード一覧と表示アニメーションの遅延上限。並び順は受け取った配列を維持する |
| `src/screens/ComposePanel.tsx` | 下書き、ペルソナ、投稿・返信処理、AI処理、引き出しの状態と配置 |
| `src/components/compose/` | スタンプ一覧、ツールボタン、評価結果の表示。必要な値と操作をpropsで受け取る |

投稿パネルのCSSは引き続き `screens/ComposePanel.css` にあります。スタンプの棚の選択は親パネルに保持し、引き出しを閉じても選択が失われない構成です。

## 自動確認

`frontend/app` で実行します。テストはVitest・React Testing Library・jsdomを使用し、API境界をモックします。実サーバへの投稿は行いません。

```sh
npm ci
npm test
npm run lint
npm run build
```

`npm test` はテストコードの型チェックも含みます。

- `tests/navigation.test.ts`: おきにいり → 公開プロフィール → 投稿 → 返信の戻り順、サイドバー選択、ログアウト時の履歴消去。
- `tests/feed.test.ts`: 通常・空・読み込み中の取得、エラーからの復帰、カードを残す再取得と通常の再読み込みの違い。
- `tests/timeline.test.tsx`: おすすめ／通常一覧、アニメーション遅延の上限、投稿・プロフィール・リアクションの操作先。
- `tests/composer.test.tsx`: 150文字制限、スタンプ挿入、評価結果の無効化、変換結果の適用、AI評価／生成の独立した可用性、拒否時の下書き保持、返信先とペルソナ制約。

## 実ブラウザでの確認

jsdomのテストは見た目や実APIとの結合を保証しません。接続済みの開発環境で `npm run dev` を起動し、次を確認してください。

1. ホームのおすすめ／通常一覧を開き、ノーマル・ダーク・園児UIと狭い画面で見た目を確認する。`?feed=empty`、`?feed=loading` でも表示を確認する。
2. ゲストで投稿・リアクション・おきにいりを操作し、ログイン案内が出ることを確認する。
3. ログイン後、おきにいり → 公開プロフィール → バブル → あやす詳細へ進み、「もどる」で同じ経路を逆順に戻れることを確認する。
4. プロフィールの「大好き」を付け外しし、おきにいり一覧に反映されることを確認する。
5. 投稿欄に150文字／151文字を入力し、151文字でも編集できるが送信できないことを確認する。スタンプを途中に挿入し、棚の選択が開閉後も維持されることを確認する。
6. 評価・変換を使い、変換結果を選んでも自動投稿されないことを確認する。`?ai-eval=off` では投稿不可、`?ai-transform=off` では通常の投稿が可能なことを確認する。
7. バブルへの返信でペルソナを切り替え、お母さんのあやすへの返信では赤ちゃんに限定されることを確認する。
8. リアクション後に一覧がローディングへ戻らず、手動再読み込みではローディングになることを確認する。ログアウト後に「もどる」で本人専用画面に戻れないことを確認する。
