# color-check（仮配色ラボ）

配色を決めるための検討ページです。素の HTML/CSS/JS だけで動き、ビルドも依存パッケージもありません。

**アプリ本体の実装ではありません。** このページの UI・レイアウトは画面設計の参考にしないでください
（[`../../CLAUDE.md`](../../CLAUDE.md)「見た目・フロント」）。app を写しているのは「見本」の部分だけです。

役割名と数値の正本は [`../../DESIGN.md`](../../DESIGN.md) §2。ここで色を確定させたら、
**DESIGN.md の frontmatter と [`../app/src/tokens/theme.css`](../app/src/tokens/theme.css) の両方へ書き戻します。**

## 何が触れるか

**ダークを既定にしています。**

| 操作 | 内容 |
| --- | --- |
| テーマ | ノーマル / ダーク / 園児UI。骨格は共通で、差し替わるのは色だけ（DESIGN.md §1.2） |
| 見本のペルソナ | あやすを書くペルソナ。選んだ側の色が入力欄の縁と見出しに出る（投稿は常に赤ちゃん） |
| プリセット | **おやすみ（既定）**、DESIGN.md の3テーマの値、§2.3 の失敗例、ダークの地の試作5案 |
| ここから動かす | 地の明るさ・地の暖かさ・線の臙脂・塗りの臙脂を1段ずつ。テーマごとの面の並びは崩しません |
| 役割トークン | §2.1 のトークン契約 21色を hex で直接編集 |
| 判定 | §2.2「配色を差し替えるときの条件」、§2.3 のダーク固有の条件、それと「主役は赤ちゃん」を測ります |
| 赤ちゃんの枠（試作） | 主役のバブルの枠を `hairline` と臙脂寄りで切り替えて比べます |
| ホバー | 見本の押せるところは実際の `button`。カーソルと <kbd>Tab</kbd> で状態が変わります |

「ダークの地の試作」以外のプリセットは、値がすべて DESIGN.md 由来です。
探索は「いま入っている値を1段ずつ動かす」だけなので、どこから来た色か分からなくなりません。
元に戻すボタンでいつでも DESIGN.md の値へ戻せます。

## おやすみモード（ダークの既定）

「真っ暗より紺系で夜空っぽく、おやすみモード的な雰囲気」＋「このSNSはあくまで赤ちゃん側が主役。
お母さんのあやすに目が奪われる」という決定（2026-08-26）から作った案で、**ダークの既定**にしています。

地は紺（下の試作の「紺」と同じ）。変えたのはそれと、**お母さんの緑**です。

### お母さんの緑を主役より弱くした

指摘は測ると裏づけられました。DESIGN.md のダークは、脇役のはずのお母さんの緑が
主役の赤ちゃんの臙脂より**強い**状態でした。

| テーマ | 赤ちゃん `accent-line` | お母さん `mother` | 差 |
| --- | --- | --- | --- |
| ノーマル | 6.77:1 | 5.54:1 | **+1.23**（赤ちゃんが前） |
| 園児UI | 5.43:1 | 4.96:1 | +0.48（差が薄い） |
| ダーク（DESIGN.md） | 7.40:1 | 9.08:1 | **−1.68**（お母さんが前） |
| おやすみ | 7.48:1 | 6.33:1 | **+1.15**（赤ちゃんが前） |

色相と彩度は変えずに明度だけ落として `#7FC79A` → **`#4AAA6E`** にしました。
ノーマルの差（+1.23）とほぼ同じ +1.15 になるので、テーマをまたいで序列が揃います。
`mother-fill` は `#468F63`、`mother-soft` は `#1B2627` に合わせて落としました。

**意味色の `success` は `#7FC79A` のままです。** あちらは「とどいた」の合図で、
ペルソナの序列とは別の話なので一緒に落としていません。

判定に「主役は赤ちゃん」を1件足しました。DESIGN.md には無い条件なので、出典
（人間の決定 2026-08-26）をコードにも書いてあります。おやすみ以外のダーク案は、
この1件だけを落とします。

### まだ残っている不均衡（構造の判断が必要）

**比を直しても、面積は直っていません。** あやすカードは緑の枠が1周するので、
枠が `hairline` の赤ちゃんのバブルより広い色面を持ちます。ここを直すには構造の決定が要ります。

1. あやすカードの枠を `hairline` にして、緑はチップと左端だけに残す
   → [`../app/src/components/SootheItem.css`](../app/src/components/SootheItem.css)
2. 赤ちゃんのバブルの枠に臙脂を混ぜて、主役側を強くする
   → [`../app/src/components/BubbleCard.css`](../app/src/components/BubbleCard.css)

**2 はラボのトグルで実際に比べられます**（既定でオン）。オフにすると app の現状（`hairline`）になります。

### 夜空の光

`--aura-cool` を `--mother`（緑）ではなく `--hairline`（地の明るい段）から作るように変えました。
紺の地に緑の光を置くと夜空ではなく「暗い森」に見えるためです。暖色側の `--aura-warm` は
`accent-line` のまま弱く残して、夜の部屋の灯りにしています。役割トークンからの派生なので生の hex は増えていません。
採るなら [`../app/src/tokens/theme.css`](../app/src/tokens/theme.css) と
[`../app/src/App.css`](../app/src/App.css) 側の変更になります。

## ホバーの決めごと（試作）

「カーソルがそこにあることを分かりやすくしたい」という指示（2026-08-26）で入れました。
見本の押せるところは実際の `button` なので、マウスでもキーボードでも確認できます。決めごとは2つだけ：

- **面のもの** … `ink` を 8% 重ねて1段持ち上げ、枠線を `accent-line` にする
- **臙脂の塗りのもの** … `accent-press` に差し替える

`ink` を重ねる形にしたので、ダークでは明るく・ライトでは暗くなり、どのテーマでも同じ規則になります。
テーマごとの分岐も、新しい色も要りません。

**浮かせていません。** BubbleCard.css の「ホバーで浮かせない。押した反応は面色で返す」を守り、
影も拡大も足さず、押した瞬間だけ `--press-scale`（0.985）で縮みます。

自分の面を持つ要素（吹き出し・リアクション）は透かしではなく自分の面色に混ぜています。
透かしにすると面が消えて地が透けるためです。逆にあやすの本文は透かしにしています。
自分の面を与えると、お母さんの `mother-soft` が消えて役割が読めなくなるからです。

### app 側で足りていないところ

見本に入れたホバーのうち、app にまだ無いものです。

| 要素 | app の現状 | ファイル |
| --- | --- | --- |
| リアクション | `:active` だけ。**`:hover` が無い**（transition は書かれている） | [`ReactionRow.css`](../app/src/components/ReactionRow.css) |
| セグメント | `:active` だけ。**`:hover` が無い** | [`SegmentedTabs.css`](../app/src/components/SegmentedTabs.css) |
| あやすの本文 | `:active` だけ。**`:hover` が無い** | [`SootheItem.css`](../app/src/components/SootheItem.css) |
| 入力欄 | `:hover` が無い | [`TextField.css`](../app/src/components/TextField.css) |
| 吹き出し | `:hover` で枠が `accent-line` になる（あり） | [`BubbleCard.css`](../app/src/components/BubbleCard.css) |

いちばん押される「リアクション」に `:hover` が無いのが、指摘の主な原因だと思います。

## ダークの地の試作（まだ採用されていません）

「真っ黒だけでなく紺色系も見たい」という依頼で作った5案です。**DESIGN.md には無い値で、
採用済みの配色ではありません。** どれを採るか（あるいは採らないか）は人間の決定が必要です。

| 案 | canvas | surface | card | hairline | 性格 |
| --- | --- | --- | --- | --- | --- |
| 墨 | `#171616` | `#1E1D1C` | `#262524` | `#343230` | ほぼ無彩色。暖色も寒色も抜いた基準 |
| 鉄紺 | `#141619` | `#1A1D20` | `#212429` | `#2C3138` | いちばん弱い紺。青灰色 |
| 紺 | `#11151C` | `#161B24` | `#1C222E` | `#262E3E` | 紺そのもの |
| 藍 | `#12121B` | `#171723` | `#1D1E2D` | `#27283D` | 紫寄りの紺 |
| 葡萄 | `#1A1316` | `#22181D` | `#2B1F25` | `#3A2A32` | 臙脂と同じ体温を保った暗色 |

**変えているのは7色だけです。**

- 地の4色 … 色相と彩度だけを差し替え、**明度の段（8.8 / 11.4 / 14.5 / 19.6%）は
  DESIGN.md ダークのまま**。面の階層の作り方を変えていません
- 役割ごとの沈んだ地（`accent-soft` / `baby-soft` / `mother-soft`）… 役割色を地に混ぜて作りました
  （臙脂 15% / 緑 12%）。色相をずらすと臙脂が紫に、緑がオリーブに寄って役割が読めなくなるためです。
  この比率だと `surface` との面色差が 1.19 / 1.16 で、DESIGN.md ダークと同じ値になります
- 文字・臙脂・緑・意味色 … **DESIGN.md ダークの実測値をそのまま使っています**

5案とも §2.2・§2.3 の条件 23件すべてを満たします（値の持ち上げは不要でした）。

### 決めてほしいこと

**§2.3 は「地は `#1A1513` の暖色寄りにして、ノーマルの生成りと同じ体温にする」と理由づけています。
紺・藍は意図的に冷たい地なので、この理由づけから外れます。** 条件は満たしていても、
ノーマルと並べたときにブランドの体温が揃わなくなる点は、判定では出ません。

温度を保ったまま真っ黒から離れたいなら葡萄、思想を変えて夜の色にするなら紺・藍、という分かれ方です。
文字は5案とも暖色の生成り（`#F4EDE4`）のままなので、紺の上では「夜の部屋の紙」に見えます。
文字も冷やしたい場合は役割トークンで `ink` / `body` / `muted` を直接触ってください。

## ダークの臙脂について

ダークの要点は、**臙脂 `#9B3342` を暗い地に置くと 2.54:1 で、文字にも枠線にもアイコンにも使えない**ことです
（DESIGN.md §2.3）。だから線・文字用の `accent-line` と塗り用の `accent-fill` が別の値になります。
「ダーク・臙脂そのまま」プリセットを押すと、これが判定で 8件の不足として出ます。

## 見るところ（おやすみモード）

- 紺の地が「夜空」に見えるか。真っ暗より落ち着くか、逆に冷たく見えないか
- **赤ちゃんのバブルが主役に見えるか。**お母さんのあやすに目が奪われないか
- 臙脂が地に溶けていないか。線用の薄紅と塗り用が、別の色として成立しているか
- 影が効かないぶん、canvas → surface → card の面色差だけで階層が読めるか
- 本文が滲まないか。暖色の生成り `#F4EDE4` が紺の上で黄ばんで見えないか
- カーソルを乗せたとき、どこにいるかが迷わず分かるか
- イラストとブランド素材が、紺の地で浮いていないか

配色案そのものへの意見は Issue（`type:discussion`）へお願いします。

### app と違えている点

- テーマの属性名が `data-theme` ではなく **`data-cc-theme`**。このページは Artifact として共有していて、
  その閲覧側が閲覧者のテーマを `data-theme` に書き込むため、名前がぶつかります
- `prefers-color-scheme` を見ていません。検討対象のテーマは常に明示的に選びます
- 左のパネルの色は候補色から作っていません（固定値）。`canvas` に `ink` と同じ色を入れても
  操作するところが読めなくならないようにしています

## 既知の制限

- 園児UI の鮮やか色（`vivid-*`）は実測済みのため編集対象外で、色見本としてだけ出しています
- `mother-fill` にはしきい値を置いていません。DESIGN.md が塗り専用と書いているだけで、
  下限を決めていないため、測った値を参考値として出しています
- DESIGN.md の frontmatter の `kid` に `on-accent` の記載がありません。
  実装（`theme.css`）が持っている `#FFFDF9` に合わせています
