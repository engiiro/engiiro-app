## 2. 目的と適用範囲

### 2.1 サービスの目的

弱音を吐いてよい場所と、それを受け止めたい人をつなぐ、エンジニアのための本音吐露SNS。本名や所属を明かさずに愚痴・弱音を投稿でき、それに対して共感や労いが返る体験を提供する。

### 2.2 適用範囲

本書は次を対象とする。

- アカウントとペルソナ
- バブル（投稿）
- あやす（コメント）
- リアクション、スタンプ
- フォロー
- タイムライン
- プロフィール
- AI文章評価、AI文章変換
- モデレーションと秘匿・安全要件
- 認証、権限、プライバシー
- 決定済みの非機能要件と受入条件

### 2.3 適用対象外

- 実装手段の選定（アルゴリズム、ライブラリ、モデル構成）
- 内部処理フロー、クラス・関数・モジュール構成
- データベースのキー設計およびスキーマ詳細
- 公開APIおよび内部APIの完全なJSONスキーマ
- 認証方式の具体、タイムアウト値、リトライ回数、ログ保存期間
- UIデザインおよび画面レイアウトの詳細

上記は全体設計書または詳細設計書の担当範囲とする。

## 3. 用語・ロール

### 3.1 用語

| 用語 | 定義 |
|---|---|
| **バブル** | 赤ちゃんペルソナとして投稿する本文。愚痴・弱音の吐露にあたる |
| **あやす** | 他者のバブルに対するコメント。赤ちゃんペルソナまたはお母さんペルソナを選んで行う |
| **リアクション** | バブル・あやすに対する肯定的な反応。対象によって利用できる種類が異なる（9.1参照） |
| **通常リアクション** | バブルおよび赤ちゃんとしてのあやすに対して使える3種。**おぎゃー／よしよし／まんま** |
<!--| **わかるわぁ（哺乳瓶）** | 通常リアクションのうちの1種。**「わかるわぁ」と「哺乳瓶」は同一のリアクションを指す2つの呼称であり、別個のリアクションとして扱わない** |-->
| **ばぶー** | お母さんとしてのあやすに対してのみ使えるリアクション。1種のみ |
| **スタンプ** | バブル本文に挿入できる画像。リアクションとは別物 |
| **アカウント** | 利用者1人に対応する内部的な単位。外部には公開されない |
| **赤ちゃんペルソナ** | 外部から見える公開アイデンティティの1つ。バブルの投稿と赤ちゃんとしてのあやすに使う |
| **お母さんペルソナ** | 外部から見える公開アイデンティティの1つ。お母さんとしてのあやすに使う |
| **推定年齢** | AIが文章から算出する年齢の目安 |

### 3.2 ロールと権限

「赤ちゃん」「お母さん」は固定の属性ではなく、行動のたびに選ぶモードである。

| ロール＼行動 | バブルの投稿 | あやす |
|---|---|---|
| 赤ちゃん | 可 | 可 |
| お母さん | **不可** | 可（ただし下記の制約あり） |

**お母さんとしてのあやすを返信先とする場合、お母さんペルソナでは返信できない。** 返信できるのは赤ちゃんペルソナのみである（8章 FR-COMMENT-005〜007）。

## 4. 共通業務ルール

### 4.1 認証が必要な操作

| 仕様ID | 仕様 | 観測できる結果・受入条件 |
|---|---|---|
| **FR-COMMON-001** | 利用者は、認証された状態でのみバブルの投稿、あやす、リアクション、フォローを行えること | 未認証状態でこれらの操作を要求した場合、操作が拒否される |
| **FR-COMMON-002** | 権限のない操作を要求した場合、その操作を拒否すること | お母さんペルソナでバブルの投稿を要求した場合、投稿は作成されない |
| **FR-COMMON-003** | 入力制約に違反した内容は保存しないこと | 制約違反時、対象データが作成・更新されていないことを確認できる |
| **FR-COMMON-004** | 操作が拒否された場合、利用者に理由が分かる表示を行うこと | 拒否時に何らかの利用者向けメッセージが表示される |
| **FR-COMMON-005** | 内部識別子である `accountId` を、外部向けレスポンスに含めないこと | 公開系の応答を検査したとき `accountId` が含まれていない |

### 4.2 未ログインで利用できる範囲

「弱音を吐く」という行為そのものは認証済み利用者に閉じるが、サービスの雰囲気を知ってもらうための**閲覧**は未ログインでも行える。

| 仕様ID | 仕様 | 観測できる結果・受入条件 |
|---|---|---|
| **FR-GUEST-001** | 利用者は、認証なしでタイムラインを閲覧できること | 未認証の状態でタイムライン取得を要求すると、バブルの一覧が返る |
| **FR-GUEST-002** | 利用者は、認証なしでバブル詳細とそのあやす一覧を閲覧できること | 未認証の状態でバブル詳細・あやす一覧の取得を要求すると、内容が返る |
| **FR-GUEST-003** | 利用者は、認証なしで他人の公開プロフィールを閲覧できること | 未認証の状態で公開プロフィールの取得を要求すると、内容が返る |
| **FR-GUEST-004** | **未認証の状態でタイムラインを取得した場合、似た境遇レコメンド（FR-FEED-003）は適用せず、新着順で返すこと** | 未認証時のタイムラインが新着順になっており、認証時とは並びが異なりうる |
| **FR-GUEST-005** | バブルの投稿、あやす、リアクション、フォロー、および本人専用の画面・情報（自分のプロフィール、フォロー中一覧）は、認証なしでは利用できないこと（FR-COMMON-001の再確認） | 未認証でこれらを要求すると拒否される |

| **FR-ACCOUNT-004** | アカウント登録時に、利用者本人の生年月日を入力できること | 登録時に生年月日を入力すると、その値がアカウントに保存される |

| **FR-ACCOUNT-006** | 本人は、自分が登録した生年月日を、本人専用プロフィールで確認できること | 本人専用プロフィールの応答に生年月日が含まれる |

| **FR-AUTH-005** | **ログインIDまたはパスワードが誤っている場合、どちらが誤っているかを区別せずに認証を拒否すること** | ログインIDが存在しない場合とパスワードが誤っている場合とで、同じ結果が返る |

## 9. リアクション・フォロー仕様

### 9.1 リアクション

リアクションは**対象によって利用できる種類が異なる**。

**呼称について：「わかるわぁ」と「哺乳瓶」は同一のリアクションである。** 2種類のリアクションとして実装してはならない。
**この「わかるわぁ」と「哺乳瓶」のリアクションに関して、「まんま」で統一することとなった**3.1用語を参照。

| 対象 | 利用できるリアクション |
|---|---|
| バブル | おぎゃー／よしよし／わかるわぁ（哺乳瓶） |
| 赤ちゃんとしてのあやす | おぎゃー／よしよし／わかるわぁ（哺乳瓶） |
| お母さんとしてのあやす | **ばぶー のみ** |

上記を踏まえた仕様は次のとおり。

| 仕様ID | 仕様 | 観測できる結果・受入条件 |
|---|---|---|
| **FR-REACT-001** | バブルに対して、おぎゃー／よしよし／わかるわぁ（哺乳瓶）のいずれかのリアクションを行えること | 3種が送信でき、バブル詳細に反映される |
| **FR-REACT-002** | 赤ちゃんとしてのあやすに対して、おぎゃー／よしよし／わかるわぁ（哺乳瓶）のいずれかのリアクションを行えること | 3種が送信でき、あやすに反映される |
| **FR-REACT-003** | **バブルおよび赤ちゃんとしてのあやすでは、通常リアクション3種のみが選択できること** | 選択肢が3種のみであり、それ以外が選択できない |
| **FR-REACT-004** | **バブルおよび赤ちゃんとしてのあやすに対して、`ばぶー` を選択できないこと** | `ばぶー` が選択肢に現れない |
| **FR-REACT-005** | **お母さんとしてのあやすに対して、`ばぶー` のみが選択できること** | 選択肢が `ばぶー` の1種のみである |
| **FR-REACT-006** | **お母さんとしてのあやすに対して、おぎゃー／よしよし／わかるわぁ（哺乳瓶）を選択できないこと** | これら3種が選択肢に現れない |
| **FR-REACT-007** | **許可されていない対象とリアクションの組み合わせを要求した場合、保存しないこと。画面上の非表示のみで担保しないこと** | クライアントを改変して不正な組み合わせを要求しても、リアクションが作成されていない |
| **FR-REACT-008** | **否定的・攻撃的なリアクションを提供しないこと** | 利用可能なリアクションが上記の対象別の種類のみである |
| **FR-REACT-009** | **「わかるわぁ」と「哺乳瓶」を、別個のリアクションとして提供しないこと** | 通常リアクションの選択肢が3個であり、4個以上になっていない |
| **FR-REACT-010** | **同一利用者は、同一対象・同一種類のリアクションを最大5回まで送信できること**（人間決定、2026-08-25） | 同じ対象に同じ種類のリアクションを5回まで送信でき、件数として反映される |
| **FR-REACT-011** | **6回目以降の同一対象・同一種類のリアクション要求は保存しないこと** | 6回目の要求に対して、リアクション件数が5から増えない |
| **FR-REACT-012** | 対象ごとのリアクション件数として、全利用者の合計回数と、自分が送信した回数の両方を取得できること | バブル・あやすの応答に、種類ごとの合計件数と自分の送信回数が含まれる |
| **FR-REACT-013** | 利用者は、自分が送信したリアクションを取り消せること | 取り消し要求後、該当分の件数が減り、再度同じ種類を送信できる |

### 9.2 フォロー

| 仕様ID | 仕様 | 観測できる結果・受入条件 |
|---|---|---|
| **FR-FOLLOW-001** | フォローは利用者単位ではなくペルソナ単位で行えること | 赤ちゃんペルソナとお母さんペルソナを個別にフォローできる |
